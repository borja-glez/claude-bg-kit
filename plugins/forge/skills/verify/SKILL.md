# forge: verify surfaces

`FORGE` means `node "${CLAUDE_PLUGIN_ROOT}/dist/forge.cjs"`. Speak in the user's language.

A surface is `.forge/verify/<name>.md` (in git): an optional YAML header (`affects`: globs of the files whose changes make it worth checking, as a list (checked at depth `flow`) or as `{flow: [...], smoke: [...]}`, where a change that only touches `smoke` globs gets a `smoke` check; `tools`: free names of tools it uses) and a free-text body saying how to start and check it, plus a `## Aprendido` / `## Learned` section of dated notes.

- **List:** `FORGE surfaces` (surfaces and detected drafts). Show name, title, affects and tools.
- **Permissions** are tied to the surface's content: the whole file except the Learned lines that `FORGE surfaces learn` added (it records each one). Only the person grants one: run `FORGE local set surfaces.<name> allowed` only after they asked here for that text (the two cases below) or answered «Sí, siempre» to the question of `/forge:run`. Any other edit — a commit, a PR, a task or an implementer that touched the file, a line added to Learned by hand — makes `verify-plan` report `permission: changed`, and the person is asked again with the diff; you never re-allow it yourself.
- **The user explains how to check something** ("para probar el Bluetooth usa el emulador con fake-scale.js"): write or update `.forge/verify/<name>.md` with the Write/Edit tools — the body in the user's words (summarised if long), a header with the `affects` and `tools` you can infer (or none), and the Learned section in the user's language. Do not ask for confirmation: the user asked. Then `FORGE local set surfaces.<name> allowed` (they described it on this machine), commit the surface alone (pathspec; add `.forge/.gitignore` when git does not track it yet) and say in one line which file you wrote.
- **Edit:** change what the user asks with Edit, then `FORGE local set surfaces.<name> allowed` again and commit it; never touch the Learned notes unless asked. To add Learned notes use `FORGE surfaces learn --name <name> --notes-file <f> --heading Aprendido` (or `Learned`), never Edit: the lines it adds never ask for the permission again.
- **Verify by hand** (`/forge:verify <name>`): name the folders `manual-<date>-<hhmm>` (the time, so two runs of one day do not share them) and run `FORGE verify-env --task manual-<date>-<hhmm> --dir .forge/work/manual-<date>-<hhmm>/reviews-1-1` (its own port and browser profile), then spawn `forge:forge-verify` (or the agent `FORGE agents` maps `verify` to) with that surface, the code checkout (this checkout), its `port`, `profileDir` and `env`, depth `smoke`, no brief (the check is "it starts and its main screen or output looks right"), review and evidence dirs `.forge/work/manual-<date>-<hhmm>/reviews-1-1/` and `.forge/work/manual-<date>-<hhmm>/evidence/1-1/`, the limits from `.forge/config.yaml`, the absolute `FORGE` path (resolve `${CLAUDE_PLUGIN_ROOT}` first) and the tools that `FORGE tools --surface <name>` reports as `missing` or `unknown` (a name forge could not find on PATH nor among the configured MCP servers; the agent tries it). After it returns, close it in one call: `FORGE verify-close --task manual-<date>-<hhmm> --dir .forge/work/manual-<date>-<hhmm>/reviews-1-1 --evidence .forge/work/manual-<date>-<hhmm>/evidence/1-1/ --locale <es|en>` (it records the result, adds the `learned` notes, turns defects into proposals, and stops what the agent left running and frees its port and profile). Report the result and show the screenshot paths.
