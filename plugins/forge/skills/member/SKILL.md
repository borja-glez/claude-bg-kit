# forge: run member

`FORGE` below means `node "${CLAUDE_PLUGIN_ROOT}/dist/forge.cjs"`. `WP` = `FORGE waypoint-cli` (run it as `node "<WP>" <command>`). From the prompt: `<plan>`, `<T>` and `<COORD>` (the coordinator's id, the `<SID>` after `run member of`). `<SID>` is this session's own waypoint id (step 1). `<project>` = the plan's `project`; `DB` = `.waypoint/<project>/dbcache`; `NOW` = `node "<WP>" now`; `EID` = `node "<WP>" event-id <SID>` (a new one per event, note or message). Before spawning agents, resolve `${CLAUDE_PLUGIN_ROOT}` to an absolute path.

A coordinator in mode `sessions` (forge:run, `references/execution.md` step 4 `start` or `relaunch`) launched this session in the worktree `.claude/worktrees/task-<T>` on its task branch (`branch` of `swarm worktree`). It does only that task, without triage or a gate, and then stops. This skill and `${CLAUDE_PLUGIN_ROOT}/skills/run/references/task-steps.md` hold all a member needs: do not load forge:run nor `/waypoint:work`. The files the task steps cite are next to it, in `${CLAUDE_PLUGIN_ROOT}/skills/run/references/` (`review-close.md`, `verify.md`, `convergence.md`, `execution.md`): read each one when a step sends you there.

## Rules

- **Language.** Every message to the person, every note and every `revert` text is in the language the person writes in (the plan's language when you have no message of theirs), not that of this skill or a CLI output. Between tool calls write nothing, or one short line.
- **Unattended.** A run member never stops to ask. Any question becomes a question note on the roadmap (ArtifactData `set` `notes/<EID>` `{ts: NOW, type: "question", author: "session:<SID>", text, taskId: T}`) and you take the safe path:

  | Situation | Safe path |
  |---|---|
  | A verify surface not allowed, or changed | Not verified in that step: `verify-skip` logged; the question note only on `note: true`. |
  | A conflict that repeats | Escalated; the task stays blocked or in conflict. |
  | A proposal outside the policy | Left pending for the user. |

- **Decisions.** Each decision you take in place of the person (a safe path above) is recorded with `FORGE decision add --session <SID> --data-file <f>`, never with `FORGE log`. Write the file with the Write tool in `<WORK>/`: `{"point": "safe-path", "what": "<one line>", "chosen": "<what you did instead>", "alternatives": ["<the others>"], "why": "<one line>", "by": "unattended", "ifWrong": {"cost": "<low|medium|high>", "note": "<one line>"}, "safePath": "<the row above>", "revert": "<how to undo it, or why it cannot be undone>", "undo": {"type": "none", "reason": "<the same reason>"}, "task": "<T>"}` (`ifWrong` as forge:run `references/decisions.md` says) (`undo` may also be `{"type": "git-revert", "base": "<sha>", "head": "<sha>", "shas": ["<your commits>"], "cwd": "<this worktree>"}` when there are commits to revert). Exit 2: fix what the message names and run it again. Send the `publish` it prints (the decision note) in one `batch`, as it is.
- **Files.** Change the project's files with the Edit and Write tools, never with `sed -i`, `awk`, `perl -i` or by rewriting them through shell redirection (they can change line endings). Saving a command's output to forge's own work files (`FORGE validate ... > .forge/work/...`) is fine. Never put user text or JSON inside a shell string: write a file and pass its flag (`--data-file`, `--detail-file`, `--text-file`). Never delete, revert, move or overwrite a file this task did not create.
- **Agents.** Always name the agent you spawn (subagent type `forge:<agent>`, roles mapped by `FORGE agents`); never let work inherit your own model; give subagents the absolute path of `forge.cjs`. Start every Agent prompt of the task with the line `forge-task: <T>-<n> @<project>`, or with the `taskLine` the CLI printed for it.
- **Never** integrate, merge or push: the coordinator integrates the task branch into the run branch, and a conflict there is its fix round (`swarm retry --adopt`), not yours.
- **Roadmap writes.** `TV` and `SV` are the newest versions you hold of `state/T` and `sessions/<SID>`. Every printed write follows forge:run `references/roadmap-writes.md` (the collections, the pin rule). A `version_mismatch` on `state/T` is waypoint's lost task (`/waypoint:work`, «Lost task»): `get` it; if its `owner` is no longer `<SID>`, another session recovered the task: never overwrite it, empty `.waypoint/<project>/pending-commits.jsonl`, tell the user, send the new owner a `reply` (`messages/<EID>` as in step 5, `taskId: T`, no `replyTo`) naming the task branch and its last commit, then `sessions/<SID>` `{status: "idle"}` and stop; otherwise retry with the new version. On `sessions/<SID>`: `get`, take its version as `SV`, retry once. Any other failure: append the intended write as one JSON line to `.waypoint/<project>/queue.jsonl`, say so in one line and go on; replay it at the next step.
- **Leases.** Your lease lives in `sessions/<SID>` and in the task's `exec`, which the `publish` of `FORGE swarm report --lease` renews. Renew both to `NOW + 10 min` at every step; before you dispatch a long agent, to `NOW + its expected budget` (at most 90 min). A lease that runs out is how the coordinator sees this session stopped and relaunches it.

## 1. Join

1. **Plan.** `node "<WP>" validate <plan>`. `URL` = its `artifacts.roadmap`; with none, tell the user that a member needs the roadmap and stop.
2. **Names.** Call `ListAgents`: its first line reads `This session is <name> [<id>] — …`; `AGENT` = the name before the bracket. `BRANCH` = `git rev-parse --abbrev-ref HEAD`; `WORKTREE` = `git rev-parse --show-toplevel`; `MAIN` = the path on the first `worktree` line of `git worktree list --porcelain` (the main checkout).
3. **Session.** If `.waypoint/<project>/session.json` exists with this `plan`, reuse its `sessionId` as `SID`, keep its `agentName` as `PREV_AGENT` and refresh `agentName` to `AGENT`. Otherwise `SID` = `node "<WP>" session-id <name>` with name `<T>` and write `.waypoint/<project>/session.json` (Write tool): `{"plan": "<plan>", "url": "<URL>", "sessionId": "<SID>", "track": null, "agentName": "<AGENT>"}`. A SID used with forge has only letters, digits, `_`, `.` and `-` (no `~ : @ +`), at most 120 characters.
4. **Register.** ArtifactData `get` `sessions/<SID>`. If it is `status: "active"`, its `heartbeatAt` is less than 15 minutes old and its `agentName` is neither `AGENT` nor `PREV_AGENT`, another live session uses this SID: take `<SID>-2` (then `-3`, … until one is missing or not held by such a session), store it in `session.json` and say so in one line. Then `set` (missing) or `update` pinned (present) `{name: "<T>", track: null, heartbeatAt: NOW, status: "active", agentName: AGENT, branch: BRANCH, worktree: WORKTREE}`; its version is `SV`.
5. **Join the execution.** `FORGE swarm join --session <SID> --role executor --task <T> --name wp-<project>-<T> --hook-session ${CLAUDE_SESSION_ID}` → `{runId, role, task, coordinator, branch, mode, project}`; `branch` is the run branch. `<WORK>` = `.forge/work/<project>/<T>` with that `project`: this task's work folder, the same relative path in `<MAIN>` and in this worktree. `--hook-session` is Claude's own id for this session (filled in above), the one its hooks receive; it differs from `<SID>`, and the hooks find this member by it. If `join` returns a `warning` (the id was not filled in), go on and tell the user once that this session will not show its own live signal. If `join` refuses your id, tell the user and stop. A member only acts on its own task: `report` and `worktree --member` refuse any other. Then `node "<WP>" bind <plan> --via forge-member --claude ${CLAUDE_SESSION_ID}`: the seat of this worktree is this conversation's. Exit 4 whose `previous.task` is `<T>` (the session this one relaunches): run `bind` again with `--resume`. Otherwise (exit 3: another live conversation holds it; exit 4: an earlier conversation left another task in progress on it) say so in one line and go on.

## 2. Handover

If `<MAIN>/<WORK>/handover.md` exists (a relaunch wrote it), read it before anything else: it names the last stage, round and the commits on the task branch. Do not repeat a step whose output is already written.

## 3. Claim

**Claim.** ArtifactData `get` `state/T`, then `FORGE swarm report <T> --session <SID> --stage brief --claim` (after a handover, the stage and round it names, without `--claim`: the task is already yours, with its `startedAt`) → one `batch`: its `publish` pinned to the version just read (forge built the claim and the `exec`), its `event`, and `update` `sessions/<SID>` `{role: "executor", runId, currentTask: T, heartbeatAt: NOW, leaseUntil: <NOW + 10 min>, status: "active"}` pinned to `SV`. Keep the returned versions as `TV` and `SV`. A `version_mismatch` on `state/T` means another live session holds the task: tell the user and stop.

## 4. Work

First `FORGE swarm worktree <T> --member <SID>` → `{worktree, branch, base, work, resumed, prior}` (this worktree; it creates nothing): `<base>` is its `base`, and a non-empty `prior` (commits of an earlier attempt on the task branch) goes to step 1 of the task steps as `prior.json` and `--prior-file`. Read `${CLAUDE_PLUGIN_ROOT}/skills/run/references/task-steps.md` now and run its steps (brief, implement, validate, verify and review, verdict) in your own worktree (`--cwd <this worktree>`; `<base>` as just said), with your own implementer, reviewers and verify agents. A step that exits 2 «not trusted»: follow their **Commands not trusted.** Your work files (`<WORK>/`: briefs, reports, validators, review dirs) live in this task worktree, your working directory, not in the main checkout; only `handover.md` and `deferred.json` are written to `<MAIN>/<WORK>/`.

Where those steps say `FORGE swarm task <T> --stage <S> …`, publish each stage with `FORGE swarm report <T> --session <SID> --stage <S> [--agent <A>|--no-agent] [--round <n>]` instead (it writes `.forge/execution/<T>.json` in the main checkout, which the coordinator's tick mirrors), and publish it with the one `batch` those steps say. When you dispatch a long agent, add `--lease <NOW + its expected budget, at most 90 min>` to that `report` and put the same `leaseUntil` in `sessions/<SID>` (forge already put it in the `exec` of its `publish`); otherwise renew with `--lease <NOW + 10 min>` at every step. `report` refuses a task whose public file another live session holds: then stop and tell the user. The steps' "step 5 renewal" is this lease rule; `proposals pull` reads `DB/proposals` after `node "<WP>" clean-cache <plan> proposals` and an ArtifactData `list` of `proposals` (`query: {limit: 1000}`, `out_dir: DB`).

**Implementer.** The first attempt goes to the implementer the steps name (the triage's `implementer.agent`: `impl-high` for a task the plan marks `delicate`). Every fix round goes to the implementer `FORGE review-close` prints (`implementer.agent`; `resume` keeps the same one, `impl-heavy` on the attempt it marks `last`): spawn that one and never compute the ladder by hand. Log every implementer you spawn, first attempt and fix rounds, with `FORGE log --kind agent --task <T>-<n> --data-file <f>` (`{"agent":"<name>","role":"<role>"}`): `FORGE review-close` reads the previous rung from it. Give each implementer the `validate` command `FORGE prep` printed for the brief (task-steps step 1); it runs it as given.

When an agent runs, wait for it (it wakes you when it returns); never end the turn with a reviewer missing and no agent running. Agents reply in two lines; read their files only when a step needs them.

## 5. Finish

**Finish.** When the verdict is `done`:
1. Commit any task change left on the task branch, titled as the brief's `Commit title` says.
2. List `meta` and `plan` into `.waypoint/<project>/dbcache` (`clean-cache`, then `list`; `done|block --db` need them). Write the summary (one sentence in the person's language) to `<WORK>/summary.txt` with the Write tool, then `node "<WP>" done <plan> --db .waypoint/<project>/dbcache --session <SID> --task <T> --state-version <TV> --session-version <SV> --summary-file <WORK>/summary.txt` → `{batch, metrics}`.
3. Apply its `batch` with one ArtifactData `batch` (the task done with its commit and summary, the `done` event, your session without a task), then its `metrics` in a call of its own, as it is, pinned if `meta/metrics` exists (a clash on the metrics never undoes the delivery). Then empty `.waypoint/<project>/pending-commits.jsonl` (write an empty file).
4. `FORGE swarm report <T> --session <SID> --stage verdict --status accepted --no-agent`.
5. Send `<COORD>` a `reply`: ArtifactData `set` `messages/<EID>` `{ts: NOW, from: SID, to: "<COORD>", type: "reply", taskId: T, text: "<T> done", status: "open"}` (when the last review-close printed `deferred` findings, you wrote them to `<MAIN>/<WORK>/deferred.json` as the steps say: the text is `"<T> done, <k> deferred in <WORK>/deferred.json"`), and SendMessage to the `agentName` of `sessions/<COORD>` with `[waypoint reply <T>] ` and the same text (if it fails, the document is enough). You have no closing report: the coordinator's lists those findings for the person.
6. `update sessions/<SID>` `{status: "idle"}` pinned, and stop.

A run member never integrates and never merges: the coordinator does.
**Blocked.** `breaker` or `stalled` with blocking findings: `FORGE swarm report <T> --session <SID> --stage <S> --status blocked`, a question note naming what the person can do, the reasons review-close printed written to `<WORK>/blocked.txt` and `node "<WP>" block <plan> --db .waypoint/<project>/dbcache --session <SID> --task <T> --state-version <TV> --session-version <SV> --by external --why-file <WORK>/blocked.txt` (`meta` and `plan` listed as in **Finish**): one `batch` with its `batch`, then, in a call of its own, the `publish` of that `report`, pinned to the version of `state/T` that batch returned; empty `pending-commits.jsonl`; a `reply` to `<COORD>` as above with `text: "<T> blocked"`; `sessions/<SID>` `{status: "idle"}`; and stop.

## 6. Resume

When SessionStart says to resume this session with /forge:member, it already joined: run `join` again with the same flags (step 1.5), renew both leases and continue from the last stage you reported (`<MAIN>/.forge/execution/<T>.json`, and `<WORK>/` in this task worktree). A manual member (role `manual`) resumed this way is not a run member: invoke forge:run --join and follow its `### Manual member` (`references/manual-member.md`) instead.
