# A task's steps

Shared by forge:run (the coordinator, Execution step 4, for tasks of mode `subagents`) and forge:member (a run member, in its own session). `FORGE`, `WP`, `DB`, `SID`, `<plan>` and `<project>` mean what the skill that sent you here says. Where a step cites a section of forge:run (Medium step 3b, Medium step 6, Execution step 4 `integrate`, step 5), read that section in `../SKILL.md` when you reach it.

**A task's steps** (the coordinator runs them for tasks of mode `subagents`; a run member runs the same steps in its own session, forge:member. State in the execution: `FORGE swarm status` shows each task's stage, agent, round and worktree; record it with `FORGE swarm task <T> --stage <S> --agent <A>|--no-agent --round <n>` at every change, which also writes `.forge/execution/<T>.json`; mirror the same `{stage, agent, round, since}` into `state/T.exec` with ArtifactData, pinned). When you dispatch an implementer, reviewer or verify agent for a task, you will not step while it runs, so lease for it: pass `--lease <NOW + the agent's expected budget, at most 90 min>` to that `FORGE swarm task` call, put the same `leaseUntil` in `state/T.exec` and in `sessions/<SID>` (ArtifactData, pinned); when it returns, the 10-min renewal of step 5 resumes. `<n>` is the brief number (1 unless a `redo` starts a new brief). Before the first task, list `proposals` into `DB` and run `FORGE proposals pull --dir DB/proposals`. After each stage change and each verdict also `update state/T` `{forge: {path, phase, agent, validators: [{name, ok}], verdict: {action, score}, round, cap}}` pinned to `TV` (the task's version), small, no findings text (`path` is the path of the task's latest triage: step 4's once it ran); on `version_mismatch` follow waypoint's lost-task rule.
1. **brief**: `mkdir -p .forge/work/T && FORGE brief --plan <plan> --task T > .forge/work/T/brief-1.md`, add what the task needs from the design and from earlier tasks, and the absolute worktree path with "work only inside this directory". `FORGE triage --plan <plan> --task T --cwd <worktree>` (in the worktree, so it sees the validators the run branch already has); its `implementer` is who implements the task in step 2. Then `FORGE validate --all --path large --base-run --task T-1 --cwd <worktree> > .forge/work/T/baseline-1.json`.
2. **implement**: spawn the implementer, the triage's `implementer.agent` as printed (a plan task is never implemented by the coordinator: a Trivial one goes to `mech`, a Large one to `impl` (`impl-high` on a sensitive zone)), or `impl-high` when the design marks the task delicate; in fix rounds, the implementer `FORGE round` prints (`implementer.agent`; `resume` keeps the same one) and never compute the ladder by hand; log every implementer you spawn, first attempt and fix rounds, with `FORGE log --kind agent --task <T>-<n> --data-file <f>` (`{"agent":"<name>","role":"<role>"}`) (a delicate task logs `impl-high`), since `FORGE round` reads the previous rung from it, **in the background**, with the brief, the worktree, the report path and the absolute FORGE path. Ask it to commit in the worktree on `task/<T>` with the brief's `Commit title prefix` and to reply in two lines; everything else goes to its report file.
3. **validate** (when it returns; `<base>` is the `base` that `swarm worktree` printed, or the one moved after a conflict retry, step 4 `integrate`): `FORGE validate --all --path large --base <base> --baseline .forge/work/T/baseline-1.json --task T-1 --cwd <worktree> > .forge/work/T/validators-<n>.json`.
4. **verify** and **review**: a plan task is first sized again (still stage `validate`) with `FORGE triage --plan <plan> --task T --cwd <worktree> --base <base>` (the same `<base>` as step 3, also after a conflict retry): it sizes the task again from its real diff (the real diff alone sizes it, the plan-time estimate sets no floor; a sensitive zone, from its text, its plan zones or its diff, keeps it at Medium at least; and across the task's fix rounds the size only goes up) and its `review` says who reviews it. Then `FORGE verify-plan` as Medium step 3b with `--path` the path it printed (and `--cwd <worktree>`; on Trivial and Small it verifies only when the task asks for it). Then spawn exactly the reviewers of `review.reviewers`, each as its `agent`, passing the Agent tool's `model` and `effort` when the reviewer's `model` and `effort` are not null (a light review is one `review-correctness` on Sonnet at medium effort, so this session never reads the diff itself), and `verify` when chosen, **in the background, in parallel**, with the brief, `git -C <worktree> diff <base>..HEAD` (after a conflict retry, `git -C <worktree> diff forge/run-<project>...HEAD`) saved to `.forge/work/T/diff-<n>.patch`, the validators file and the review dir `.forge/work/T/reviews-<n>-<round>/`, plus, for `review-correctness`, the implementer's report path when the brief has a `TDD: required` line. Each replies in two lines. A path that grows to Large here is reviewed with the reviewers it prints, and is not blocked, also when the execution is unattended (the Large row of `### Unattended` is about a request triaged Large before any work).
5. **verdict**: when the last of them returns (each one that returns without its file is respawned at once; never end the turn with one missing and no agent running), `FORGE verdict --task T-1 --dir .forge/work/T/reviews-<n>-<round> --validators .forge/work/T/validators-<n>.json` plus exactly the flags of `review.flags` (none for a light review) as Medium step 6, and `FORGE round --task T-1 --path large`. `done` → `FORGE swarm task <T> --stage verdict --status accepted --no-agent`. `resume`, `fresh-stronger` or `redo` → back to implement with the findings and the implementer `FORGE round` prints (Medium step 6 rules, cap 4); steps 3 and 4 then run again, sizing included, and the reviewers follow the new size. `breaker` or `stalled` with blocking findings → `FORGE swarm task <T> --status blocked --detail-file <f>` and the waypoint blocked path for `state/T`.
