# Manual member

Read from forge:run (`### Manual member` in `SKILL.md`). `FORGE` means what that skill says.

`/forge:run --join` (also what `/waypoint:work` §0.6 sends here): a session the user drives joins a running execution and works plan tasks next to it. `MAIN` = the path on the first `worktree` line of `git worktree list --porcelain`. Read `<MAIN>/.forge/execution.json` for `runId`, `coordinator` and `branch`; `<plan>` is the plan of its `project`.
1. **Join.** `SID` with `/waypoint:work` §0 Setup items 1–4 (item 6 is what sent you here). `FORGE swarm join --session <SID> --role manual --hook-session <CSID>` (`--hook-session` is Claude's own id for this session, the one its hooks receive: the hooks find this member by it; a `warning` means it was not filled in: go on and tell the user once that this session will not show its own live signal); ArtifactData `update` `sessions/<SID>` `{role: "manual", runId, heartbeatAt: NOW, leaseUntil: <NOW + 10 min>, status: "active"}` pinned; renew that lease at every step.
2. **Take a pending task** ("coge una tarea pendiente"): list `state` and `sessions` into `DB` as `references/execution.md` step 2 does, then `FORGE swarm next --plan <plan> --db DB --session <SID>` → `{task, reason}`. With a task: ArtifactData `get` `state/T`, then one `batch`: `update state/T` `{status: "in_progress", owner: SID, claimedAt: NOW, startedAt: NOW, exec: {runId, mode: "manual", by: SID, agent: null, stage: "brief", round: 0, since: NOW, leaseUntil: <NOW + 10 min>}}` pinned to the version just read, and a `started` event (`sessions/<SID>` keeps `role: "manual"`); the session that loses the race (`version_mismatch`) asks `next` again. Then `FORGE swarm worktree <T> --member <SID>` → `{worktree, branch, base, setup}`, work there (by absolute path, `--cwd`; an implementer you spawn there gets the `validate` command of `FORGE prep --task T-1 --path <path> --cwd <worktree>`, as `references/task-steps.md` steps 1 and 2 say), and publish each stage with `FORGE swarm report <T> --session <SID> --stage <S> [--agent <A>|--no-agent] [--round <n>]` (it writes `.forge/execution/<T>.json` in the main checkout, which the coordinator's tick mirrors), mirrored into `state/T.exec` pinned, and renew the task's lease (`state/T.exec.leaseUntil`) with your own. With no task, tell the user the `reason`.
3. **A task the execution already runs** (the user asks for it by id): do not touch it. Say who runs it and at which stage (`FORGE swarm status`, `<MAIN>/.forge/execution/<T>.json`) and offer another one.
4. **New work.** Add it to the plan as a new task with its track, `depends_on`, zones and `done_when`, a plan commit and the sync from the main checkout (`/waypoint:plan`), then ask the user whether this session does it (the default) or the coordinator; the coordinator's tick picks it up when it is left to it.
5. **Finish.** Commits on `task/<T>`, the task `done` with its commits (`/waypoint:work` §4), `FORGE swarm report <T> --session <SID> --stage verdict --status accepted --no-agent` (so its public file does not linger as running), and a `reply` with `text: "<T> done"` to the coordinator, which integrates it. If your zones overlap a running task, send the coordinator an `overlap_warning` (`/waypoint:work` §6) before you touch them. Then go back to step 2 if the user wants to go on.
