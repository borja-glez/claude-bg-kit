# Decisions

Read from forge:run (`## Decisions` in `SKILL.md`). `FORGE`, `WP`, `SID` and `<id>` mean what that skill says. `<WORK>` is the task's work folder: `.forge/work/<id>` outside an execution; in an execution, the `work` that `FORGE swarm worktree` printed.

A decision you take in place of the user because nobody is there to ask (an unattended execution: the safe paths of `### Unattended` in `references/execution.md`) or because autonomy is `auto` (`references/autonomy.md`) is recorded with `FORGE decision add --data-file <f>`, never with the generic `FORGE log` (it skips the checks and the summary lens reads). Attended rulings stay `FORGE log --kind ruling` and go in the report's rulings, as the paths of `SKILL.md` say: the user is there and sees them. Write the file with the Write tool in `<WORK>/`:

`{"point": "<route|triage|design-apply|design-approve|plan-confirm|mode|ruling|safe-path|other>", "what": "<one line>", "chosen": "<the option taken>", "alternatives": ["<the others>"], "why": "<one line>", "by": "<auto or unattended>", "revert": "<how to undo it, in the user's language>", "undo": <one of the shapes below>, "task": "<id>", "resolves": "<the id of the question note it answers, only when it does>"}`

A `safe-path` decision also carries `"safePath": "<the row of the table in ### Unattended of references/execution.md it followed>"` (one line, at most 200 characters): the situation it met («A verify surface not allowed, or changed», «A Large task»…), while `chosen` says what it did instead. It is kept with the decision (`FORGE decision show <n>`); a decision written without `chosen` shows it there instead, and one without either shows its `what`.

`undo` is `{"type": "git-revert", "base": "<sha>", "head": "<sha>", "shas": ["<each commit you made, oldest first>"], "cwd": "<dir, when the commits are not in this checkout>"}`, `{"type": "design-reopen", "project": "<id>"}`, `{"type": "plan-edit", "project": "<id>", "tasks": ["<the ids it added>"]}`, `{"type": "branch-discard", "branch": "<name>"}` or `{"type": "none", "reason": "<why it cannot be undone>"}`. Always write `revert`: one sentence in the user's language on how to undo it, or, when nothing can, why not and what to do instead (then `undo` is `{"type": "none", "reason": "<the same reason>"}`). It prints the event with its number `n`; during an execution it carries the run's `runId`. Exit 2 means the file is wrong: fix what the message names and run it again. A `git-revert` names its exact commits in `shas` (1 to 50, each read with `git rev-parse HEAD` right after you made it): `decision add` checks that each is in `base..head`, and a revert undoes those and never another session's commits in that range.
- **With a roadmap** (`artifacts.roadmap` in a `docs/waypoint/*/plan.yaml`): add `--session <SID>` (`SID` = this session's waypoint id, or `main`) to `FORGE decision add`. It prints `publish`, the writes of the decision note (what, chosen, why, alternatives, how to undo it, `auto`) and, when the file names the question note it answers (`"resolves"`, which needs `--session`), the update that closes that question; send them in one ArtifactData `batch`, as they are (`references/roadmap-writes.md`). With `resolves`, list `notes` into `DB` and add `--db DB`: a question someone already answered is left as it is, and `resolvesRefused` says so (tell the person in one line). The texts of the file are in the user's language.
- **Without a roadmap:** when the task closes, `FORGE decision md --scope <scope> --locale <es|en>` (the user's language: `es` for Spanish, `en` for anything else; `<scope>`: the execution's `runId`, else the task id without a brief suffix `-<n>`). It writes `docs/forge/decisions/<scope>.md` only when the scope has automatic decisions and prints `written` and `path`; commit that file with the task's work, or in a small `forge: decisions` commit right after it. In a plan execution the work is on the run branch: run it with `--cwd .claude/worktrees/run` before `FORGE swarm merge` (`references/execution.md` step 7) and commit the file there (`git -C .claude/worktrees/run`), so it lands with the run. An ephemeral execution writes it in this checkout after its last integration.
- **Report.** Every report that closes work (Medium step 7 in `SKILL.md`, `references/large.md` step 5, `references/execution.md` step 7, `references/ephemeral.md` step 4) ends with a section «Decisiones automáticas» (in the user's language) built from `FORGE decision list --auto --task <id>` (`--run <runId>` for an execution): one line per decision, `n. <what> → <chosen> (<why>) · revertir: <revert>`. Leave the section out when the list is empty. The user lists them with `/forge:decisions` and undoes one with `/forge:decisions revert <n>`. When the project has a roadmap and the work closed is a Small or Medium task outside an execution (a Large closes through its execution: `references/execution.md` step 7), also `FORGE roadmap-run --task <id> --session <SID>` (add `--project <project>` for a plan task) and ArtifactData `set` its `write` (`runs/<runId>`, the summary the roadmap lists).
