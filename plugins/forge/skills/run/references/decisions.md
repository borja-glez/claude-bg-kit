# Decisions

Read from forge:run (`## Decisions` in `SKILL.md`). `FORGE`, `WP`, `SID` and `<id>` mean what that skill says.

A decision you take in place of the user because nobody is there to ask (an unattended execution: the safe paths of `### Unattended` in `references/execution.md`) or because autonomy is `auto` (`references/autonomy.md`) is recorded with `FORGE decision add --data-file <f>`, never with the generic `FORGE log` (it skips the checks and the summary lens reads). Attended rulings stay `FORGE log --kind ruling` and go in the report's rulings, as the paths of `SKILL.md` say: the user is there and sees them. Write the file with the Write tool in `.forge/work/<id>/`:

`{"point": "<route|triage|design-apply|design-approve|plan-confirm|mode|ruling|safe-path|other>", "what": "<one line>", "chosen": "<the option taken>", "alternatives": ["<the others>"], "why": "<one line>", "by": "<auto or unattended>", "revert": "<how to undo it, in the user's language>", "undo": <one of the shapes below>, "task": "<id>"}`

`undo` is `{"type": "git-revert", "base": "<sha>", "head": "<sha>", "cwd": "<dir, when the commits are not in this checkout>"}`, `{"type": "design-reopen", "project": "<id>"}`, `{"type": "plan-edit", "project": "<id>", "tasks": ["<the ids it added>"]}`, `{"type": "branch-discard", "branch": "<name>"}` or `{"type": "none", "reason": "<why it cannot be undone>"}`. Always write `revert`: one sentence in the user's language on how to undo it, or, when nothing can, why not and what to do instead (then `undo` is `{"type": "none", "reason": "<the same reason>"}`). It prints the event with its number `n`; during an execution it carries the run's `runId`. Exit 2 means the file is wrong: fix what the message names and run it again.
- **With a roadmap** (`artifacts.roadmap` in a `docs/waypoint/*/plan.yaml`): also ArtifactData `set` `notes/<EID>` (`EID` = `node "<WP>" event-id <SID>`, `WP` = `FORGE waypoint-cli`, `SID` = this session's waypoint id, or `main`) `{ts: NOW, type: "decision", author: "session:<SID>", text: "<what> → <chosen>: <why>", taskId: "<T, when there is one>", decision: {point, what, chosen, alternatives, why, revert, auto: true}}`, the texts in the user's language.
- **Without a roadmap:** when the task closes, `FORGE decision md --scope <scope> --locale <es|en>` (the user's language: `es` for Spanish, `en` for anything else; `<scope>`: the execution's `runId`, else the task id without a brief suffix `-<n>`). It writes `docs/forge/decisions/<scope>.md` only when the scope has automatic decisions and prints `written` and `path`; commit that file with the task's work, or in a small `forge: decisions` commit right after it. In a plan execution the work is on the run branch: run it with `--cwd .claude/worktrees/run` before `FORGE swarm merge` (`references/execution.md` step 7) and commit the file there (`git -C .claude/worktrees/run`), so it lands with the run. An ephemeral execution writes it in this checkout after its last integration.
- **Report.** Every report that closes work (Medium step 7 in `SKILL.md`, `references/large.md` step 5, `references/execution.md` step 7, `references/ephemeral.md` step 4) ends with a section «Decisiones automáticas» (in the user's language) built from `FORGE decision list --auto --task <id>` (`--run <runId>` for an execution): one line per decision, `n. <what> → <chosen> (<why>) · revertir: <revert>`. Leave the section out when the list is empty. The user lists them with `/forge:decisions` and undoes one with `/forge:decisions revert <n>`.
