Read from forge:infinite (`references/autonomous.md`, a product run, every cycle). `FORGE`, `WP`, `NOW`, `SID`, `<CSID>`, `<plan>` and `DB` mean what that skill says, and `<n>` what `references/autonomous.md` says; `EID` = `node "<WP>" event-id <SID>`, as for every note.

A `product` run builds a product from its vision, the project's `docs/waypoint/<n>/design.md`: what it is, who it is for, its pillars, the quality criteria of a professional product of that kind, and what it is not. On top of the cycle of `references/autonomous.md`, it researches the market at its start and whenever a phase closes, puts each new task in the phase it belongs to, and reviews the whole roadmap when a phase closes. Only this file is read every cycle; the start and the phase close have their own.

## At the start

`references/autonomous.md` step 5 reads `references/product-start.md` and does it: the market research before the plan, and its note sent once the roadmap is published.

## Each cycle

The cycle of `references/autonomous.md`, with these changes:
- **The market note.** §3.4's `forge-scout` and the cycle's `forge-critic` also get the file `FORGE market last` prints, when it is not null.
- **Approved to tasks (§3.2).** A product run puts each new task in the phase it belongs to, with a `done_when` a check can see, what it waits for and an estimate; never in the improvements phase `PX`:
  1. `FORGE proposals to-task <id> --plan <plan> --db DB`, without placement flags, takes the placement of the critic's `keep` that approved it.
  2. Exit 2 that says `no phase of the plan is open`: every phase of `<plan>` with tasks is done and none is empty, so nothing can be placed. Do `## When no phase is open` below, then step 1 again for this approval and the ones after it. No debt note per proposal for this state.
  3. Exit 2 about its placement (the message names `--phase`: no `keep` placed it, as for an idea the person insisted on or one the owner approved on the page, or the critic's placement no longer holds): place it yourself, by the critic's rules: a phase of `<plan>` that is not done (an empty one is fine), never `PX`; a `done_when` that says what a check sees, more than the title, written with the Write tool to `.forge/work/infinite/done-when-<id>.txt`; the tasks it waits for; an estimate such as `45m` or `2h`. Then run it once more with them: `FORGE proposals to-task <id> --plan <plan> --phase <F> --done-when-file .forge/work/infinite/done-when-<id>.txt --estimate <e> --depends-on <ids> --db DB` (`--depends-on T004,T007` only when it waits for tasks).
  4. Its placement refused again (the message says the placement does not hold): ArtifactData `set` a debt note `notes/<EID>` `{ts: NOW, type: "debt", author: "session:<SID>", text, proposalId: "<id>"}`, its text naming the proposal and what the CLI printed. It waits for the person (`run.saturation` lists it in `waiting.unplaced`): while that note is in `DB/notes`, §3.2 skips it.
  5. Exit 2 because it has no mark of the roadmap's owner: skip it, as §3.2 says. Exit 2 that says `list state first`: list `state` into `DB` (`node "<WP>" clean-cache <plan> state`, then ArtifactData `list` it with `query: {limit: 1000}` and `out_dir: DB`) and run it again.

  A refused placement never sends the proposal to `PX`, nor back to the critic.
- **A fresh state.** Right after §3.3, before the phase check below and before §3.4's scout and critic, list `state` into `DB` again (`node "<WP>" clean-cache <plan> state`, then ArtifactData `list` it with `query: {limit: 1000}` and `out_dir: DB`): §3.3's `/waypoint:work` listed it before its task was done, so without it the task just finished reads as not done, its phase never closes, and the critic places new work into that phase.
- **A phase that closes.** Then, every cycle, whether a task finished or not (so a close cut short goes on), run `FORGE infinite phase --plan <plan> --db DB` from the worktree: it reads the proposals, the marks and the ledger of the directory it runs in. It prints `{closed, phases, held, reviewed}`: `phases` each phase's `{id, done, total}` (an empty phase never closes), `held` the tasks a re-plan may not change, each with its `reason`, and `reviewed` the phases already reviewed. With `closed` not null, do `## When a phase closes` for that phase now, before §3.4.
- **The rounds.** An exploration round is the scout and the critic (`references/autonomous.md`). The market runs at the start and at every phase close, so the rounds that end a run read the market of its last phase close.

## When a phase closes

When `FORGE infinite phase` gives `closed`, read `references/phase-close.md` now, and again every time, and do it for that phase: the market, the review of the whole roadmap, its re-plan, its findings and any vision change.

## When no phase is open

The approvals that wait are the run's own decisions, taken under delegation: the run opens the phase they need through the re-plan path, instead of leaving them to the person, at most once per cycle. All from the worktree, with the files of `OP` = `.forge/work/infinite/open-phase-<cycle>/` (`OP/ops.json` is `.forge/work/infinite/open-phase-<cycle>/ops.json`). With `OP/opened.txt` there, this cycle opened one: go on with **Place them**. With `.forge/work/infinite/open-phase-refused.json` there, an earlier attempt was refused and its debt note waits for the person: open none, and skip each approval that says no phase is open.

1. **The phase.** Write `OP/ops.json` with the Write tool: `{"ops": [{"op": "add-phase", "id": "<F>", "name": "<name>", "goal": "<goal>"}]}`, one phase whose id no phase of `<plan>` has, named for what these approvals are for, with the goal they share; it goes after the last phase. Write the why to `OP/why.txt`: which approvals wait and what the phase is for, in one paragraph in the person's language.
2. **Check.** `FORGE proposals replan-check --ops OP/ops.json --plan <plan> --db DB`, then `node "<WP>" replan <plan> --ops OP/ops.json --why-file OP/why.txt --check`, which prints `{changes}` and writes nothing.
3. **The decision.** Write `OP/decision.json` as forge:run `references/decisions.md` says: `point` `replan`, `what` «open <F>: <its name>», `chosen` adding the phase, `why` from `OP/why.txt`, each alternative with its `whyNot` and `tradeoffs`, «leave the approvals to the person» always one of them (its `whyNot`: they are the run's own approvals, and only a phase places them; its `tradeoffs`: the person would choose the next phase, and the approved work would wait for them), `by` `auto`, `revert` in the person's language (revert the plan commit whose title names this decision, then sync with `/waypoint:plan`), and `undo` `{"type": "none", "reason": "git-revert of the plan commit that comes after it, whose title names this decision"}`. `FORGE decision add --data-file OP/decision.json --session <SID>` prints its number `n` and its `publish`: write the output to `OP/decided.json`, and send the `publish` in one ArtifactData `batch`, as it is.
4. **The write.** `FORGE proposals replan-check` again, as **Check** says, then `node "<WP>" replan <plan> --ops OP/ops.json --why-file OP/why.txt`, and commit the plan alone: `git commit -m "Open phase <F> (decision <n>)" -- <plan>`. Sync with `/waypoint:plan` from the worktree: its own plan commit runs only when `git status --short -- <plan>` shows that the sync changed the plan. Then write `OP/opened.txt` with the Write tool, one line naming `<F>`.
5. **Place them.** Back in **Approved to tasks**, step 1 for each approval: the CLI refuses the critic's placement in a done phase, naming `--phase`, and step 3 places the task in `<F>`.

**Refused.** Exit 2 of **Check** or of **The write**: the plan stays as it is. First write `.forge/work/infinite/open-phase-refused.json` `{"debt": "<EID>", "debtSent": false, "revert": null, "problems": "<what it printed>"}`; then ArtifactData `set` one debt note for the state, not one per proposal, `notes/<EID>` `{ts: NOW, type: "debt", author: "session:<SID>", text}`, saying that no phase of `<plan>` is open, which approvals wait and what the CLI printed, and `"debtSent": true` in the marker. A refusal of **The write** comes after the decision: also record its `revert`, as `references/phase-close.md` says in **Not carried out** (its file `OP/revert-<n>.json`), and its number as the marker's `"revert"`. On resume, send only what the marker lacks.

**Resume.** With `OP/decided.json` there, the decision is recorded (its `n`): when a commit of `<plan>` names it (`git log --oneline -F --grep "(decision <n>)" -- <plan>`), go on from the sync in **The write**; when `git status --short -- <plan>` shows the plan changed, from its commit; otherwise from **The write**.
